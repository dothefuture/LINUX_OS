# Процессы в Linux: конспект

По лекции 4 «Процессы в Linux. Команды для работы с процессами».

## Что такое процесс

Процесс — это программа во время выполнения. У него есть свои данные и ресурсы: память, открытые файлы, доступ к устройствам. Один и тот же файл программы можно запустить несколько раз — тогда появится несколько отдельных процессов.

Linux выполняет много процессов одновременно. Операционная система распределяет между ними процессорное время: одни процессы работают, другие ждут своей очереди или завершения какой-либо операции. Процесс также может запустить другой, дочерний процесс.

У каждого процесса есть **PID** (его номер), **PPID** (номер родительского процесса), владелец и приоритет. Процессы образуют дерево; его корень — процесс с PID 1 (обычно `systemd` в современных дистрибутивах).

PID помогает обратиться к конкретному процессу, например при завершении. PPID позволяет понять, какая программа его запустила. Когда процесс заканчивает работу, он возвращает код завершения: `0` обычно означает успешное выполнение.

## Состояния процесса

| Обозначение | Значение |
| --- | --- |
| `R` | Выполняется или готов к выполнению. |
| `S` | Ожидает событие; ожидание можно прервать сигналом. |
| `D` | Ожидает операцию ввода-вывода; обычным сигналом ожидание не прервать. |
| `T` | Остановлен, например для отладки. |
| `Z` | Завершился, но родитель ещё не получил код завершения («зомби»). |

Состояние процесса меняется во время работы. Например, программа может сначала выполняться (`R`), затем ждать чтения файла (`S` или `D`), а после снова продолжить выполнение. Состояние `Z` не означает, что программа всё ещё работает: она уже закончила, но запись о ней пока остаётся в таблице процессов.

## Запуск и просмотр

Обычная команда запускается на переднем плане: терминал ждёт её завершения. Если добавить в конце `&`, команда запустится в фоне и терминалом можно будет пользоваться дальше. Это удобно для долгих операций.

Команда `jobs` показывает задачи, запущенные из текущей оболочки. `fg` возвращает задачу на передний план. Сочетание `Ctrl+Z` приостанавливает текущую задачу, а `bg` продолжает её в фоне. Номер вроде `%1` — это номер задачи в `jobs`, а не PID процесса.

```bash
sleep 60 &
jobs
fg %1
```

Здесь `sleep 60` ждёт 60 секунд. После запуска в фоне его можно увидеть через `jobs`, а затем вернуть в терминал командой `fg %1`.

## Как посмотреть процессы

`ps` показывает снимок списка процессов на момент запуска команды. `ps -e` выводит процессы всей системы, а `ps -f` добавляет подробности, в том числе PID и PPID. `pstree` показывает процессы в виде дерева и помогает увидеть связи между родителями и дочерними процессами.

```bash
ps
ps -ef
pstree
```

`top` обновляет сведения о процессах и загрузке системы в реальном времени. Там можно посмотреть, сколько процессорного времени и памяти потребляет программа. Для выхода из `top` нажимают `q`. В отличие от `ps`, список на экране постоянно меняется.

## Выполнение позже и после выхода из терминала

`at` выполняет команду **один раз** в заданное время. После `at 13:15` вводят нужную команду и завершают ввод сочетанием `Ctrl+D`. Запланированные задания можно посмотреть через `atq`. Для работы `at` соответствующая служба должна быть установлена и запущена.

`nohup` позволяет программе продолжить работу после закрытия терминала. Часто его сочетают с `&`, чтобы сразу вернуть управление оболочке. Если вывод не перенаправлен отдельно, он обычно записывается в `nohup.out`.

```bash
echo 'date' | at 13:15
nohup ./script.sh &
```

## Приоритет и сигналы

Приоритет влияет на то, как процесс получает процессорное время при конкуренции с другими процессами. `nice` задаёт значение *nice* при запуске, а `renice` меняет его у уже работающего процесса. Диапазон обычно от `-20` до `19`: чем меньше число, тем выше приоритет. Обычный пользователь может увеличить nice своего процесса, но для уменьшения значения могут потребоваться права администратора.

```bash
nice -n 5 команда
renice -n 10 -p 1234
```

Во втором примере `1234` — PID процесса. Изменение nice не ускоряет программу само по себе: оно влияет на распределение ресурсов, когда процессор занят.

Сигнал — это сообщение процессу о событии или команда на определённое действие. `Ctrl+C` посылает `SIGINT` процессу на переднем плане. `SIGTERM` просит завершиться корректно, чтобы программа успела сохранить данные и освободить ресурсы. `SIGSTOP` останавливает процесс, а `SIGCONT` продолжает его работу. `SIGKILL` завершает процесс принудительно.

`kill` отправляет сигнал процессу по PID, `killall` — процессам с указанным именем. Без указания сигнала обе команды посылают `SIGTERM`. Если программа зависла, обычно сначала пробуют обычный `kill`, а принудительный `SIGKILL` используют, если процесс не завершился.

```bash
kill 1234
kill -s KILL 1234
killall имя_программы
```

В примерах `1234` нужно заменить настоящим PID, который можно узнать через `ps` или `top`. Команда `killall` может затронуть сразу несколько процессов с одним именем.
